# Common multi-lane AER qualification

Status: candidate-neutral workload and optional lane-stall suite, 2026-08-08.

## What is common

There is no architecture-specific "multi-lane event." The input is the same
logical AER occurrence trace for every candidate. A candidate declares its
native retire-lane count, and the common scoreboard observes zero, one, or
multiple completed logical events on each cycle. A single-lane candidate must
run the capacity traces; it skips only the independent-lane optional test.

The public lane-capacity manifest is
`benchmarks/clean_slate_aer/manifest.multilane-n16.json`. It is an exact 18-run
subset of the frozen 46-run `manifest.neutrality-n16.json`, checked by an
automated test. It contains:

- 16-way simultaneous and global-fan-in events;
- three seeds at 1.0, 1.25, 1.5, and 2.0 offered events/cycle;
- matched 4-event and 16-event temporal bursts; and
- two sparse-to-overload-to-recovery phase transitions.

`optional_multilane_independent_stall` is the separate optional SystemVerilog
test. It emits rotating four-source bursts and applies a different deterministic
ready/stall phase to each physical retire lane. It requires both
`output_backpressure` and `multi_lane_retirement`. Unsupported candidates report
`SKIP_UNSUPPORTED`; a binding may not add lanes or storage.

## Generate and run

Generate the public input traces without selecting any candidate:

```bash
scripts/run_common_multilane_benchmark.sh generate-only
```

Run the first registered native binding, DREC prefix, at K=4:

```bash
AER_SIMULATOR=xrun \
  scripts/run_common_multilane_benchmark.sh drec-prefix 4
```

Run the same exact traces at K=1, K=2, and K=4:

```bash
AER_SIMULATOR=xrun \
  scripts/run_common_multilane_benchmark.sh drec-prefix all
```

`drec-replicated` selects the equal-state replicated-selector reference. Other
candidates use the files generated by `generate-only` through their storage-free
native bindings. Lane count is a declared candidate capability, not a free
testbench adapter feature.

Candidates registered in `run_clean_benchmark.sh` can run the complete public
18-trace slice with one command. On the team server, Hyeonsu runs:

```bash
AER_SIMULATOR=xrun \
  scripts/run_common_multilane_candidate.sh clean rotation-priority
```

Each trace is stored under its own result subdirectory so legacy trace-mode
filenames such as `trace.csv` can never overwrite another run.

Ganghee uses the same trace loop through `run_ganghee_native_benchmark.sh`:

```bash
setenv AER_GANGHEE_TOP aer_tx16_trad_rowcol_fovea
setenv AER_GANGHEE_FILELIST /home/aiasic26911/ganghee-native.f
scripts/run_common_multilane_candidate.sh ganghee
```

Ganghee's two-lane row/column-bitmap experiment uses a separate stateless
normalization binding. It expands the two four-bit column masks into at most
eight completed address events without changing or wrapping the candidate RTL:

```bash
setenv AER_GANGHEE_CLUSTER2_TOP aer_tx16_trad_rowcol_fovea_cluster2
setenv AER_GANGHEE_CLUSTER2_FILELIST /absolute/path/to/ganghee-cluster2.f
scripts/run_common_multilane_candidate.sh ganghee-cluster2
```

This binding is eligible only for sink-always-ready traces because the native
cluster2 interface has no output-ready signals.

The 2026-08-08 Xcelium qualification and same-trace comparison are recorded in
`reports/common-multilane/ganghee-cluster2-qualification.md`.

## Required reporting

For every capacity trace report generated, source overrun, accepted, delivered,
fixed-window events/cycle, p95/p99 latency, service gap, and drain correctness.
Also report native functional pins and events/pin-cycle. Do not claim that a
four-lane candidate is four times faster unless the offered trace reaches that
rate and the downstream interface actually accepts four completed events.

The independent-stall optional test additionally requires each stalled lane to
hold valid, event, and source stable while unstalled lanes remain able to make
progress. All accepted events must be delivered exactly once after drain.
