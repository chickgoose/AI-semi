## 제안 DUT 인터페이스 요구사항

RTL 인터페이스가 아직 확정되지 않아 TB 계약과 DUT 연결을 `tb/dut_adapter.sv`로
분리했다. 실제 top의 포트명이 다르면 adapter만 변경한다.

```systemverilog
module aer_dut #(
  parameter int NUM_SOURCES = 4,
  parameter int ADDR_WIDTH  = 16
) (
  input  logic clk,
  input  logic rst_n,
  input  logic [NUM_SOURCES-1:0] in_valid,
  output logic [NUM_SOURCES-1:0] in_ready,
  input  logic [ADDR_WIDTH-1:0] in_addr [NUM_SOURCES],
  output logic out_valid,
  input  logic out_ready,
  output logic [ADDR_WIDTH-1:0] out_addr,
  output logic [$clog2(NUM_SOURCES)-1:0] out_src
);
```

계약의 의미:

1. 입력 이벤트는 `in_valid[i] && in_ready[i]`인 rising edge에 정확히 한 번 수락된다.
2. source는 수락 전까지 `in_valid[i]`와 `in_addr[i]`를 안정적으로 유지한다.
3. 출력 이벤트는 `out_valid && out_ready`인 rising edge에 정확히 한 번 전달된다.
4. DUT는 backpressure 중 `out_valid`, `out_addr`, `out_src`를 안정적으로 유지한다.
5. 각 source 내부의 수락 순서는 출력에서도 보존된다. source 간 전역 순서는 arbiter
   정책에 따르며 scoreboard는 강제하지 않는다.
6. `out_src`는 입력 source ID다. 주소가 source ID를 이미 포함한다면 유지 여부를
   팀에서 결정해야 한다.
7. `rst_n`은 비동기 active-low로 제안했다. 실제 reset 규약이 다르면 adapter와 SDC를
   함께 변경한다.
8. reset 시 수락 전/내부 대기 이벤트를 폐기하는 정책, 최대 내부 FIFO 깊이와 overflow
   동작은 RTL 사양에서 명시해야 한다.

아직 결정해야 할 항목은 `NUM_SOURCES`, `ADDR_WIDTH`, 주소 encoding, arbitration 정책,
입력별 FIFO 유무/깊이, full일 때의 동작, reset 중 handshake, 최대 허용 latency다.

## Scoreboard와 지표 정의

reference model은 입력 handshake 때 `(source, address, acceptance_cycle)`을 source별
queue에 넣는다. 출력 handshake 시 해당 source queue의 head와 비교한다. 빈 queue의
출력은 중복/비요청, 주소 불일치는 데이터 또는 순서 오류, 종료 시 남은 항목은 누락이다.

- latency: 입력 수락 edge부터 출력 전달 edge까지의 cycle 수
- throughput: 첫 입력 수락부터 마지막 출력 전달까지 `emitted / cycles`
- fairness: source별 전달 수에 대한 Jain's fairness index
- max wait: input request가 ready를 기다린 시간과 수락된 source head가 출력을 기다린
  시간 중 관측된 최대 cycle 수

현재 fairness는 제공된 부하의 전달 분포를 측정한다. 포화 상태에서 arbiter 공정성을
비교할 때는 source별 동일한 이벤트 수를 쓰는 `simultaneous` workload를 기준으로 삼는다.

## 실행

통합 브랜치에서 두 DUT를 동일 parameter와 네 workload로 실행한다. 설정을 생략하면
`scripts/config.local.sh`, 없으면 `scripts/config.example.sh`를 사용한다.

```bash
scripts/run_sim.sh baseline
scripts/run_sim.sh improved
```

file list 또는 config를 명시적으로 바꿀 수도 있다.

```bash
scripts/run_sim.sh baseline --filelist /path/to/baseline.f
scripts/run_sim.sh improved --config /secure/path/aer-flow.sh
```

PPA는 예제 config와 site-specific driver를 저장소 밖에 복사·수정한 뒤 실행한다.

```bash
AER_RUN_ID=trial-001 scripts/run_ppa.sh
# 또는
AER_RUN_ID=trial-001 scripts/run_ppa.sh /secure/path/aer-flow.sh
```

단계별 재실행은 `scripts/run_synth.sh`, `scripts/run_sta.sh`,
`scripts/run_power.sh`에 `<design> <config>`를 전달한다.

같은 run 안에서는 두 설계에 동일 SDC, corner, clock period, power activity가 전달된다.
각 driver는 `results/README.md` 형식의 `metrics.tsv`를 만들어야 하며 최종 결과는
`summary.tsv`로 합쳐진다.

## 알려진 제한과 후속 검증

- mock DUT는 TB smoke test용이며 설계 성능 결과로 사용하지 않는다.
- 현재 baseline은 payload port가 없으므로 공정한 비교 회귀에서는 주소를 source ID로
  고정한다. a1이 공통 payload interface를 제공하면 adapter만 갱신하고 unique-payload
  순서 검사를 활성화한다.
- SVA와 procedural scoreboard가 stalled output 및 X/unknown을 중복 검사한다.
- simulator가 없는 환경에서는 `scripts/self_check.sh`로 shell 문법과 필수 파일만
  검사한다.
- Power 비교용 VCD/SAIF는 동일 seed, workload, reset/측정 window로 생성해야 한다.
- 공식 corner와 제출 형식은 계속 TBD다. 현재 slow 0.9 V / 125°C는 provisional 비교
  corner이며 공식 평가 corner로 간주하지 않는다.
