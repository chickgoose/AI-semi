# A2 — 개선형 AER RTL

## 구현 범위

- `aer_sync_fifo.sv`: non-fall-through 동기 FIFO, full 상태 동시 pop/push 지원
- `aer_round_robin_arbiter.sv`: 승인 시 우선순위 이동, backpressure 중 grant lock
- `aer_event_buffer.sv`: source별 FIFO, round-robin arbitration, 단일 event 출력 결합
- `aer_dut.sv`: a3 공통 unpacked-array 인터페이스를 core의 packed-array 인터페이스로 변환
- `files.f`: improved RTL 전용 compile 순서

모든 모듈은 단일 clock, active-low asynchronous reset을 사용하며 source 수, 주소 폭, FIFO depth를 파라미터화한다. 파라미터는 각각 1 이상이어야 한다.

## core 인터페이스

내부 core는 다음 `ready/valid` 계약을 사용한다.

| 신호 | 방향 | 의미 |
| --- | --- | --- |
| `src_valid_i[N-1:0]` | input | source별 주소가 유효함 |
| `src_ready_o[N-1:0]` | output | source별 FIFO가 해당 cycle 이벤트를 수락할 수 있음 |
| `src_addr_i[N-1:0][A-1:0]` | input | source별 event address |
| `event_valid_o` | output | 출력 event가 유효함 |
| `event_ready_i` | input | receiver가 출력 event를 수락함 |
| `event_addr_o[A-1:0]` | output | 선택된 event address |
| `event_source_o[ceil(log2(N))-1:0]` | output | 선택 source ID; `N=1`이면 폭 1 |
| `occupancy_o[N-1:0]` | output | source별 FIFO 점유량(관측/성능 계측용) |

입력과 출력은 모두 `valid && ready`인 rising edge에서 한 번 전송된다. producer는 handshake까지 valid와 payload를 유지해야 한다. 출력은 backpressure 동안 grant를 잠가 payload를 안정적으로 유지한다. FIFO는 empty 상태의 combinational fall-through를 제공하지 않아 입력 수락 후 출력까지 최소 한 cycle 지연된다.

기존 AER의 request/acknowledge 4-phase 또는 pulse 인터페이스가 요구되면 이 코어 바깥에 protocol adapter를 두는 방식을 권장한다. 공식 사양 전에는 해당 adapter와 전체 transmitter/receiver를 임의 구현하지 않는다.

독립 arbiter를 직접 사용할 때 requester는 선택된 request를 `advance_i`까지 유지해야 하며, `advance_i`는 `grant_valid_o`가 유효한 cycle에만 올려야 한다. `aer_event_buffer`는 FIFO valid와 출력 handshake로 이 조건을 보장한다.

## a3 공통 wrapper

`aer_dut`은 a3의 `clk`, `rst_n`, `in_valid`, `in_ready`, unpacked `in_addr`, `out_valid`, `out_ready`, `out_addr`, `out_src` 포트를 그대로 구현한다. generate assignment로 unpacked `in_addr[NUM_SOURCES]`를 core의 packed `src_addr_i`로 변환하고 `event_source_o`를 `out_src`에 연결한다. `occupancy`는 wrapper 내부 신호로 유지하며 공통 포트에는 노출하지 않는다. `FIFO_DEPTH`는 a3의 기본값 4와 호환되는 선택 parameter다.

## 경계 동작

- empty: `event_valid_o=0`; enqueue 후 다음 cycle부터 arbitration 대상이 된다.
- full: 일반적으로 `src_ready_o=0`; 같은 source가 출력에서 pop되는 cycle에는 replacement push를 허용한다.
- 동시 요청: 현재 round-robin 시작점부터 첫 non-empty FIFO를 선택한다.
- backpressure: 선택 grant를 lock하며 FIFO를 pop하지 않는다.
- 지속 요청: 출력 전송이 진행되는 한 승인 source 다음 source로 우선순위가 이동한다.
- reset: FIFO 점유량, pointer, arbiter priority와 lock을 초기화한다. FIFO memory 내용은 valid가 아니므로 초기화하지 않는다.

## 통합 시 확인 필요

- 공식 reset polarity와 sync/async 요구
- source ID를 address에 포함할지 별도 sideband로 둘지
- source가 backpressure 계약을 지킬 수 있는지, 아니면 overflow/drop counter가 필요한지
- source별 FIFO 대신 공유 FIFO가 필요한 PPA 목표인지
- 통합 Genus run에서 내부 `occupancy`의 보존/최적화 정책

## 검증

- 로컬에는 HDL compiler가 없어 whitespace와 정적 구조를 검사했다.
- 서버 Xcelium 23.09-s013에서 `xrun -64bit -sv -f tests/a2/files.f -top aer_improved_tb`를 실행해 compile, elaboration, simulation이 모두 status 0으로 끝났다.
- 집중 회귀는 `NUM_SOURCES=3`, `FIFO_DEPTH=2`로 full FIFO 동시 pop/push의 count/order, 4-cycle 출력 stall의 address/source 고정, non-power-of-two round-robin, source당 18개 포화 이벤트의 누락·중복과 매 전송 service skew 1 이하를 검사했다.
- a3 interface, protocol assertions, scoreboard와 wrapper를 직접 연결한 Xcelium 회귀에서 simultaneous와 backpressure가 모두 `accepted=128`, `emitted=128`, `errors=0`, `fairness=1.0`으로 통과했다. simultaneous throughput은 0.992248 event/cycle, backpressure throughput은 0.403785 event/cycle이었다.
- 검증 당시 작업 중인 a3 `aer_tb.sv`는 Xcelium 예약어 `sequence`를 identifier로 사용해 원본 그대로는 parsing되지 않았다. a3 담당 경로는 수정하지 않고 임시 사본에서 이를 `event_sequence`로 의미 보존 rename하여 wrapper 연결을 검증했다. 통합 전 a3 원본에도 같은 rename이 필요하다.
