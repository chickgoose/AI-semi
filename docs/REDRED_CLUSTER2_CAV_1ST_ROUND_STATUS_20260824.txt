팀 REDRED 1차 중심 통합 현황 — cluster2_steal_buf → CAV → world grid
작성일: 2026-08-24

0. 결론

이번 1차 발표의 중심 결과는 강희의 cluster2_steal_buf AER이다.
준영의 CAV baseline은 메인 AER 뒤에 연결 가능한 2차 확장 경로를
실제 데이터로 보여주는 보조 증거로 사용한다.

현재 다음 경로가 scoped observational/software replay로 PASS했다.

  공식 UZH shapes_rotation raw event/pose/calibration
    → pinned 4×4 cyclemask
       (converter bytes도 별도 pinned됐지만 생성 과정 재현은 이번 evidence에
        포함되지 않으며, runner도 converter 자체를 다시 실행하지 않음)
    → pinned cluster2_steal_buf의 sealed Xcelium RTL simulation 관측 결과
    → TB-side event ID를 이용한 observational software exact join
    → software causal-CAV baseline
    → 512×256 world-coordinate grid

정확한 발표 표현은 “event-identity 수준의 software functional extension
feasibility를 실제 데이터로 확인했다”이다. TB-side event ID는 native AER
payload가 아니다. “확장성이 보장됐다”, “wire-level 인터페이스 호환성이
입증됐다”, “CAV까지 RTL로 구현했다”,
“AER 스케줄링이 CAV 정확도를 개선했다”라고 말하면 안 된다.

4. occurrence와 retire를 구분한 이유

event_timestamp_ns는 원본 UZH 센서 시각이고, native_occurrence_cycle은
converter 규칙으로 만든 1 ms workload bin이다. cav_occurrence_cycle은
6.5 ns software logical-cycle 값이며, retire_cycle은 Xcelium에서 관측한
native retirement cycle이다. 이 네 시각을 서로 바꾸어 쓰면 안 된다.
Geometry는 원본 event timestamp와 software CAV cycle만 사용하고, native
retire cycle과 중재 latency는 관측 sidecar에만 보존한다.

RAW-CAV, AER-OCC-CAV, AER-RET-CAV는 동일한 event ID와 occurrence-time
geometry를 가진다. AER-RET-CAV에만 native retire cycle과 latency를 별도
관측 sidecar로 보존한다. 따라서 현재 결과는 transport latency가 영상 품질에
주는 영향을 측정한 결과가 아니다.


5. PASS와 HOLD 경계

PASS:
  - sealed Xcelium native RTL simulation 관측 8,503건을 bundle에서 재검증
  - source/TB-side event ID/native occurrence의 8,503건 observational exact join
  - native overrun 0, latency histogram 보존
  - 동일 원본 UZH event timestamp 입력에 대한 software causal-CAV replay
  - 8,420 WORLD ray의 512×256 software world-grid mapping
  - 결과 JSON의 canonical encoding, seal, 입력 hash, 30-file 실행 코드
    authority 재검증
  - 외부 입력 없이 전체 bridge suite 141개 PASS, 환경-gated 3개 SKIP
  - 공식 외부 입력을 켠 8,503-event golden replay PASS

HOLD:
  - CAV/world 변환의 wire-complete RTL
  - CAV/world RTL의 Genus 합성, STA, power, Innovus P&R
  - retire timestamp를 실제 CAV geometry에 주입한 품질 비교
  - predictor, online feedback, depth/translation/parallax 보정
  - native AER이 CAV 정확도를 높인다는 주장
  - 다른 UZH sequence 및 pan/tilt 세기 구간에 대한 일반화 결론

강희 native AER의 기존 PPA/P&R 자료는 이 공식 software-CAV result의
authority에 포함되지 않는다. 현재 브랜치에서 CAV PPA는 HOLD이며, 별도
native PPA/P&R 수치를 쓰려면 강희가 원본 report 상대경로, RTL hash,
corner/constraint, vectorless 또는 VCD 조건과 signoff 한계를 함께 제시해야
한다. 별도 native 자료를 software CAV의 PPA로 합쳐 말하면 안 된다.

7. 재검증 명령

저장소 clone과 checkout:

  git clone https://github.com/chickgoose/AI-semi.git
  cd AI-semi
  git switch integration/cluster2-steal-buf-cav-bridge

외부 데이터 없이 committed authority와 unit/integration test 확인:

  python3 -B -m unittest discover \
    -s tests/redred_cluster2_cav_bridge -p 'test_*.py' -q

tracked sealed bundle에서 pinned cyclemask를 별도 빈 디렉터리로 추출:

  mkdir -p <new-empty-evidence-directory>
  tar -xzf \
    benchmarks/redred_cluster2_cav_bridge/evidence/server_native_observation_ca446aa.tgz \
    -C <new-empty-evidence-directory> \
    faer_snapshot/common_traces_uzh/uzh_shapes_rotation_patch.cyclemask.txt

공식 UZH source와 위 cyclemask까지 준비된 경우 exact golden replay:

  REDRED_RUN_CLUSTER2_FUNCTIONAL_ASSAY_OFFICIAL=1 \
  REDRED_UZH_SHAPES_ROTATION_ROOT=<official-shapes_rotation-directory> \
  REDRED_CLUSTER2_CYCLEMASK_PATH=<new-empty-evidence-directory>/faer_snapshot/common_traces_uzh/uzh_shapes_rotation_patch.cyclemask.txt \
  python3 -B -m unittest \
    tests.redred_cluster2_cav_bridge.test_official_functional_run.EnvironmentGatedOfficialGoldenReplay \
    -v

공식 실행 flag를 설정하지 않으면 전체 suite에서 환경-gated 3개가 SKIP되는
것이 정상이다. flag를 1로 설정하고 dataset 또는 cyclemask 경로를 빠뜨리면
의도적으로 FAIL한다. committed result 자체의 seal과 저장소 코드 authority
검증은 외부 입력이 없는 일반 테스트에서도 수행된다.

“REDRED 1차는 최대 두 행을 병렬 retire하는 pinned cluster2_steal_buf의
sealed Xcelium RTL simulation 관측을 중심 결과로 제시한다. 공식 UZH
8,503개 이벤트와 TB-side native identity를 observational software join하여
기존 causal-CAV software baseline으로 재생했고, 8,420개 WORLD ray의
512×256 software grid mapping을 확인했다. 이는 event-identity 수준의
software functional extension feasibility이며, wire-complete CAV RTL,
latency-quality 평가, CAV/world PPA와 predictor/feedback은 후속 HOLD다.”
