1. 지금 만드는 것
==================

16개 event source의 pending/accept부터 ordered two-lane retire까지 포함하는
complete single-posedge AER digital endpoint다.

  source_pending_i/source_accept_o
    -> A2 또는 A3 scheduler
    -> admission + charged buffering
    -> registered single-edge TX
    -> 9-wire {valid, addr0[3:0], addr1[3:0]}
    -> registered single-edge RX
    -> exact-once ordered retirement
    -> drain/error observation

Clock은 clk_i의 posedge 하나만 사용하고 reset은 synchronous active-high다.
DDR, negedge, generated/gated/forwarded clock, vendor primitive는 current 설계에
사용하지 않는다. Digital 단계에서 exact top port/filelist/module inventory와
Genus read_hdl 조건을 검사하므로 서버로 넘길 때의 인터페이스 호환성도 매
회귀에서 확인한다.


2. 핵심 아이디어와 혁신성
=========================

A2 — aggregate-weighted 성능 primary
  - [1,5,5,1] persistent interleaved weighted round-robin
  - sparse fallback과 cycle당 최대 두 event accept
  - onehot grant/calendar 경로로 timing cone을 줄임
  - 목표: source overrun 감소, accepted event 및 throughput 증가

A3 — exact scalar-prefix semantic fallback
  - held pending snapshot에 canonical scalar selector를 두 번 적용
  - exact two-selection prefix를 보존
  - exact-prefix 의미가 필요하거나 A2 고유 gate가 실패할 때의 fallback

공통 혁신 포인트
  - accepted-event correctness와 source-capacity loss를 분리한다.
      generated = source_overrun + accepted
      clean drain 뒤 accepted = retired
  - scheduler core만 비교하지 않고 buffer/TX/RX/retire/drain/error까지 같은
    complete endpoint 경계로 비교한다.
  - 257개 atomic record(idle 1 + singleton 16 + ordered distinct pair 240)를
    9-wire link cell로 표현한다.
  - A2의 aggregate 성능과 A3의 exact-prefix 의미를 하나의 임의 점수로 섞지
    않고 scalar-free Pareto와 사전 선언 정책으로 결정한다.
  - digital PASS, physical diagnostic PASS, final selection/release authority를
    분리하는 fail-closed 증거 모델을 사용한다.

World-first/최초 알고리즘/특허성은 아직 주장하지 않는다. 외부 문헌·특허
선행조사는 별도 보강 항목이다.

6. 지금 아이디어가 어디까지 진행됐는가
=======================================

팀 내부 conditional decision:
  default aggregate-weighted use -> A2 추천
  exact scalar-prefix 필요       -> A3 fallback
  scalar-free Pareto front        -> [A2, A3]

공식 최종 decision:
  official_selected_candidate = NONE
  release = HOLD

이유는 기능 또는 timing 실패가 아니다. 현재 artifact는 실제 Genus/Innovus
결과이고 동일 environment snapshot으로 묶였지만, controlled producer의
out-of-band 인증/freshness와 주최 측 최종 PDK/corner/I/O/load authority가 없다.
또 source->mapped와 mapped->postroute formal equivalence, organizer-approved
mapped-cell legality, 필요 시 VCD/SAIF activity power도 아직 최종 sign-off
증거가 아니다. 따라서 정확한 표현은 다음과 같다.

  digital correctness: PASS (hash-bound team diagnostic)
  post-route timing/DRC/vectorless: PASS_DIAGNOSTIC
  mapped structural CDC/RDC: PASS_DIAGNOSTIC_RELEASE_HOLD
  team recommendation: A2, A3 exact-prefix fallback
  official selection/release: NONE / HOLD

8. 팀원 Claude Code에 붙여넣을 짧은 지시문
===========================================

AI-SEMI 팀 REDRED의 현재 설계를 read-only 검토해라.
공개 repo는 https://github.com/chickgoose/AI-semi.git 이고, 반드시
origin/integration/redred-system-goal branch의 50e26f9 이상을 사용해라.
먼저 docs/REDRED_TEAM_STATUS_20260820.txt를 읽고 그 문서의 검증 명령을
실행해라. A2는 aggregate-weighted primary, A3는 exact scalar-prefix
fallback이다. 최신 RTL full50와 동일-snapshot GPDK045/6.5 ns post-route
diagnostic은 PASS지만 producer/freshness 및 organizer authority가 없으므로
팀 추천은 A2, 공식 candidate는 NONE, release는 HOLD다. 보고서는 실제 RTL,
정책 의도, scoped PASS, HOLD, 새 문제를 구분하고 diagnostic PASS를 sign-off나
공식 selection으로 승격하지 마라.
