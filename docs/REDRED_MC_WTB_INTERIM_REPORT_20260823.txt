1. 한 줄 요약

rotation-only MC-WTB baseline과 RG3-CAV·DSPB·SO3-PLL model/query 경로는 구현됐고
current CAV의 NEW108 효과도 측정됐다. 그러나 세 후보 실측 runner가 108-window의
대형 cycle receipt를 한 프로세스에 보존해 16 GiB 환경에서 score 이전 OOM이 발생했다.
현재 후보 알고리즘을 튜닝하는 것이 아니라 동일 결과를 유지하는 bounded-memory 공통
baseline 생성·검증 경로를 수정하고 있다.

5. 세 CAV+ 후보

RG3-CAV:

- 세 과거 committed pose로 bounded angular acceleration을 추정
- cadence/residual/direction/magnitude guard 실패 시 exact current CAV fallback
- 가속·감속·정지·반전 구간 개선이 목표

DSPB:

- current CAV, EWMA CAV, bounded RG3, signed-speed의 네 expert
- 새 pose를 보기 전에 생성한 immutable forecast만 past-pose residual로 평가
- 다음 epoch부터 credit을 반영해 outcome leakage를 막는 구조

SO3-PLL:

- measurement-time anchored angular-rate state
- 과거 forecast residual로 bounded P/I correction을 다음 epoch부터 반영
- velocity noise와 systematic lag를 feedback으로 줄이는 구조

현재 세 후보는 Python model-only다. fixed-point, SystemVerilog, Genus, Innovus 결과는 없다.

6. 2026-08-23 실측 시도와 발견된 문제

동일 NEW108와 고정 config로 세 후보 단일시도를 시작했으나 score 이전에 실행 인프라
문제가 확인됐다.

- RG3-CAV: pre-score 단계에서 Linux OOM killer 종료
- DSPB: 단독 실행에서도 anon RSS 약 14.14 GiB에서 Linux OOM killer 종료
- SO3-PLL: 메모리 보호를 위한 process stop 과정에서 wrapper exitcode 147이 기록돼
  evidence-grade 실행 무효, 이후 프로세스 종료

현재까지 후보 score/result/campaign receipt는 생성되지 않았다. 따라서 이 사건을 후보
알고리즘 성능 실패로 해석하지 않는다.

근본 원인:

- 기존 campaign108이 108-window full current-CAV evaluation을 한꺼번에 보존
- 각 window의 큰 cycle_receipts까지 전체 baseline object에 남음
- candidate native output/replay까지 같은 process lifetime에 겹침
- screen108도 같은 full baseline을 다시 만들고 전체 replay 검증하므로 campaign만
  고치면 두 번째 OOM이 발생할 수 있음

후속 source audit에서 별도의 fail-closed schema mismatch도 확인됐다.

- Stage3 adapter v3 seal은 event count를 source_window_event_count로 제공
- 현재 screen108은 존재하지 않는 selected_event_count를 조회
- adapter implementation hash도 top-level 필드가 아니라 sealed dependency manifest에
  있는데 screen108이 존재하지 않는 projection_implementation_sha256을 조회

따라서 memory 문제만 없었어도 현재 publication commit의 real screen은 provenance
검증 단계에서 중단됐을 가능성이 높다. 이 항목도 metric·후보 로직과 분리된 공통
infrastructure compatibility fix로 함께 수정하고 mutation test를 추가한다.

7. 현재 수정 중인 범위

목표는 metric이나 후보 파라미터를 바꾸는 것이 아니라 동일 결과를 bounded memory로
재현하는 것이다.

- 기존 frozen evaluator를 window별 singleton 입력으로 그대로 호출
- 각 window를 독립 integrity verification
- 다음 window로 넘어가기 전에 대형 cycle receipt 폐기
- exact registry/input/query decision/loss와 simulation record digest는 보존
- campaign108과 screen108가 같은 compact baseline builder/verifier를 사용
- 원래 결과·artifact·receipt byte equivalence를 synthetic fixture에서 검증
- Python 3.8 grammar와 append-only/fail-closed 동작 유지
- 실제 NEW108 재실행 전 peak RSS 기준을 확인

이 수정은 모델 성능 튜닝이 아니라 로컬·서버 간 실행 호환성을 위한 infrastructure fix다.

9. 혁신성 경계

event warping, constant-velocity/acceleration, model bank, PLL/feedback 자체는 선행기술이
강하므로 단독 혁신으로 주장하지 않는다.

현재 차별화 가설은 다음을 함께 묶는 complete-endpoint system contract다.

- supplied-pose authority와 strict-past causal eligibility
- equal-edge/equal-timestamp atomicity
- immutable past decision
- exact-once event semantics와 exact fallback
- event outcome을 보지 않는 pose-residual adaptation
- latency/state/PPA를 모두 charge하는 45 nm co-design

현재 판정은 SYSTEM_CONTRACT_DIFFERENTIATION_HYPOTHESIS_ONLY다. broad novelty 또는
특허성을 확립했다고 주장하지 않는다.
